# Improved Inventory 0.3.7-beta.1 candidate

Prepared 10 October 2026 for the reported house-screen lag. This is a local
performance candidate; the cause of the reported lag remains unmeasured.
Owner gameplay testing is pending. No installation, deployment, game launch,
save access, publication or external message is part of this preparation.

## Changes and evidence

The drawer callback retains the original native update, including native
tooltip and equipment behavior. A guarded snapshot batches generation,
vtable, owner, item ID and component reads. Shared view lifetime checks remain.
Direct presentation also rejects a rebound item ID or changed owner.

Hidden drawers remember the target and the transform state produced by the
native instant-layout method. A subsequent call can omit that method only
when the component pointer and target still match and all five transform
values remain within 1e-9 of the recorded state. This tolerance covers native
interpolation roundoff; NaN, infinity and larger changes force layout. Renderer
visibility is still reapplied because equipment updates can make it visible.
Visible drawers retain instant layout. Captures reset the cache; failed state
reads fall back to instant layout without caching an unreadable transform.

Static inspection of the supported executable's methods at 0x213a20 and
0x34e230 shows that their effects are position (x/y/z) and scale writes. The
house method also obtains the panel's current ref_grid bounds. The original
drawer update interpolates toward those current bounds before our hook checks
the transform. Panel movement therefore invalidates a settled hidden position.
The fixture models these writes and interpolation; it does not execute game
code or establish the actual frequency of closed-panel callbacks.

Scrolling presents only drawers in the previous or new visible window.
It retains a cheap scan of the captured array; full object virtualization,
native-update suppression and lifetime checks cached across frames are deferred.
The 1,024-drawer capture limit, item containers and save format are unchanged.

## Offline validation

The expanded layout fixture covers open/covered views, 400 and 1,024 items,
native interpolation, moving panels, each transform field, NaN/infinity,
component replacement, unreadable memory, rebound IDs, changed owners/vtables,
filter visibility changes, fresh/empty views, scroll jumps and boundaries.
Original native updates and the house toolbar update remain active.

For one stable fixture pass over 400 house drawers, guarded reads fall from
4,400 to 3,564 and instant-layout calls from 400 to 36. Equipment uses 2,770
reads instead of 3,600 and 30 instant-layout calls instead of 400. Both retain
400 original native updates. A one-row scroll touches 42 house drawers or
36 equipment drawers instead of the whole container. These are operation
counts, not measured FPS or evidence that the house lag is fixed.

The complete reader/browser/native fixture suite passed during development.
Final release compilation, startup guards and archive verification are recorded
below after packaging. Supported game/loader requirements and universal package
mapping are inherited from 0.3.6; no new gameplay compatibility claim is made.

## Package and owner check

The semantic build version is 0.3.7-beta.1. The owner-facing archive is named
ImprovedInventory-0.3.7.beta.zip, preserving the requested .beta label. It is
prepared under outputs/candidates/improved-inventory-0.3.7-beta.1-20261010.
The payload records the source commit; checksum and manifest accompany the ZIP.

With the game closed, install this as an update through the usual mod manager.
Compare idle house behavior before opening Storage, while it is open, after
closing it and after any temporary lag recovers. Use the same campaign and mod
configuration for the comparison; record total Storage and Trash counts.
Do not disable storage-capacity protection on an over-capacity main campaign.

Check scrolling in both panels, search/filter/reset, hover tooltips followed
by scrolling or closing, and close/reopen animation. On a backed-up campaign
copy, also check transfers, an emptied/repopulated panel and pre-adventure
equipment selection. The actual FPS change and native animation/input behavior
remain owner-verification requirements before stable promotion.
