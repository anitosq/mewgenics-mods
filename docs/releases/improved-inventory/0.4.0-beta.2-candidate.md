# Improved Inventory 0.4.0-beta.2 candidate

## Stage and scope

Prepared for owner testing on 22 October 2026. It replaces the untested
0.4.0-beta.1, whose single Grid button capped both containers. The owner
clarified that the game's Storage grid has a fixed size (its capacity, raised
by Butch from 3x3 to 10x10), while Trash grows with the items to discard.
This beta still includes the untested 0.3.8-beta.1 performance work.

- Two buttons on the count row, Storage and Trash, each cycle 5x5, 6x6
  (default), 7x7, 8x8 and 10x10; Trash also offers Auto (no cap, native
  growth). A size caps the native column count; beyond it the grid scrolls.
  Pre-adventure equipment uses the Storage size, with five rows per six
  columns (6x5, 8x6, 10x8).
- Choices are stored as `storage_columns` and `trash_columns` in
  `%LOCALAPPDATA%\ImprovedInventory\settings.ini`; missing, unwritable or
  damaged values keep 6x6. Storage never reads `auto`.
- Set labels drop each language's "Set Bonus" wording, as in 0.4.0-beta.1.

Not a published release. No installation, deployment, game launch or save
access was performed for this candidate.

## Implementation evidence

- Native grid layout `211700` (supported build): Storage columns (`+0x50`)
  restart at 2 when the view mode changes, then grow while columns² is below
  a count of matching list entries. Trash columns (`+0x54`) start at 4 at
  minimum and grow while columns² is below `[0x13c7560]+0xc8` + 1. Together
  with the owner's report, this suggests that the Storage count reflects
  capacity slots. Static reading has not identified those fields beyond
  this; the mod still caps the native count and never writes it.
- A cap above the native count keeps the native count (no extra backgrounds
  exist), so a Storage size at or above its capacity shows the full capacity.
- Set-name affixes per language are unchanged from 0.4.0-beta.1; see
  [its record](0.4.0-beta.1-candidate.md) for the data survey.
- Changing a size repositions the open view's existing backgrounds and
  drawers, nothing is allocated, and scrolling resets to the first row.
  More visible cells mean more native item updates while open.

## Offline checks

- Python reader tests, browser model tests (Node.js v24.21.0) and all native
  assertion fixtures pass.
- `native_grid` covers both size cycles (Storage without Auto), caps,
  equipment rows, labels, per-container settings round trips, damaged input
  and real set-name strings in all ten game languages.
- The toolbar fixture checks both button labels, cache invalidation on each
  change, control recreation and hiding during equipment selection.

## Owner test required

Install the beta through the usual manager after closing the game, on a
backed-up campaign copy. At home:

- Click Storage through each size: icon size, scrolling, arrows, wheel input
  and tooltips. A size at or above your capacity shows the whole capacity.
- Click Trash through each size and Auto; discard items and check that Auto
  grows like the unmodded game and fixed sizes scroll.
- Check that the two buttons don't overlap the counts ("No matches" included)
  or the first item row.
- Leave and reopen the house, restart the game: both choices remain.
- Pre-adventure equipment uses the Storage size.
- French set filter shows names such as "Alliage".

Fixture results do not establish visual alignment, button placement, sound or
frame rate.
