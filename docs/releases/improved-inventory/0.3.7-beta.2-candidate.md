# Improved Inventory 0.3.7-beta.2 candidate

Prepared 11 October 2026 after the owner reported continued house lag on beta 1
after opening and closing Storage. This candidate targets avoidable closed-panel
work; the actual frame-time bottleneck remains unmeasured. Preparation only:
no installation, deployment, launch, save access or publication.

## Change and evidence

House drawer updates now check the captured panel manager's generation, vtable
and active panel in one guarded snapshot. If neither inventory panel is active,
the mod skips per-item presentation and its full scene validation. The original
native update still runs, including mouse-leave and tooltip behavior. The first
captured drawer still calls the existing toolbar cleanup path. Hidden-button
hit tests use the same early negative check and pass through to native behavior
when inventory is inactive. Equipment behavior is unchanged.

Active inventory still requires the existing full view and drawer validation.
The guard is read on every matching callback, not cached between frames, so
reopening without a grid rebuild resumes immediately. Covered but active panels
keep their existing behavior. Transition-only log lines record layout suspension
and resumption when the first captured drawer updates; these are not FPS metrics.

## Offline validation

The new close-without-rebuild regression fails on beta 1 and passes with the
guard. Tests cover null/other active panels, manager reuse, changed vtable,
unreadable state, missing manager, stale scene, unrelated callbacks, covered
active inventory, both panel identities and repeated close/reopen cycles.
Small-grid cases include 0, 1, 16, 35, 36 and 37 items, plus 513 items. Existing
equipment, filtering, scroll-window and animated-transform tests remain.

A stable fixture pass over 400 closed house drawers uses 400 guarded reads
and zero instant-layout calls, versus beta 1's 3,564 reads and 36 calls. Both
retain 400 original native updates. The toolbar is stubbed in this fixture;
its once-per-pass cleanup cost is excluded. An open house pass uses 3,964 reads
and 36 calls: the new guard costs one extra read per item while open. Closed
hidden-button checks use one guarded read each instead of repeated full scene
checks. These are synthetic operation counts, not measured game frame times.

Next candidates, subject to focused validation:

- Consolidate duplicate drawer snapshots between iq_find and iq_present in the
  open update path, retaining validation immediately before writes. Do not cache
  lifetime checks across frames. This could remove one guarded read per item.
- Limit per-scroll diagnostic logging. This session logs 105 individual row
  changes in about 3.5 seconds; logging cost itself has not been measured.
- Avoid recomputing unchanged toolbar labels and set-popup rows while preserving
  per-frame panel motion and hover feedback. Text writes and set ownership counts
  already have caches; the remaining formatting/control work needs measurement.
- Profile open/scrolling inventory before full drawer virtualization. Pooling
  only visible drawers could reduce native updates, but requires preserving
  item bindings, transfers, tooltips and scene lifetime across native rebuilds.
  Current native updates deliberately remain enabled for cleanup.
