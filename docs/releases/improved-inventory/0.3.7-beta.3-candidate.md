# Improved Inventory 0.3.7-beta.3 candidate

Prepared 11 October 2026 after the owner confirmed beta 2 removes the lag after
closing Storage. This candidate implements the next two agreed optimizations:
one drawer snapshot per update and removal of per-scroll diagnostic logging.
No installation, deployment, game launch, save access or publication is included.

## Changes

The indexed lookup now validates membership and the captured view. Presentation
validates the drawer generation, vtable, owner, item ID and components in one
snapshot immediately before writing. Previously the update read this same
snapshot both in lookup and presentation. Nothing is cached across callbacks.
The house and equipment updates share this path; direct presentation from grid
capture, filtering and scrolling retains its existing identity validation.

Click suppression still validates drawer identity immediately before blocking a
hidden item or popup-covered item. Stale or rebound drawers pass to the original
native click handler. House toolbar updates require successful presentation;
missing drawer components now also prevent that drawer from driving the toolbar.
The beta-2 inactive-panel guard and native mouse-leave/tooltip updates remain.

Removed per-row scroll reports, raw wheel diagnostics and ignored-wheel messages.
The per-drawer timestamp existed only for wheel diagnostics; it is replaced by
a flag for the existing one-time callback report, removing per-update clock reads.
Startup errors, grid captures, filter results and house active/inactive transitions
remain logged. These existing transition logs verified beta 2's close behavior.

## Validation

The new 400-item read-count assertion failed on beta 2 before implementation.
The complete offline reader/browser/native suite passes with this change.
Expanded checks cover drawer generation/vtable/owner/ID changes, unreadable
identity and mismatched references after view lookup, stale native clicks,
visible/hidden/popup click behavior, and rejected drawer updates. Existing
close/reopen, small-grid, scrolling, animation and lifetime checks still pass.
A 100-scroll fixture keeps its expected row position without emitting reports.
Equipment uses a simulated native callback plus the shared update expression;
it does not execute the game's equipment code.

For a stable pass over 400 open house items, guarded reads fall from 3,964 in
beta 2 to 3,564 (about 10%). Equipment falls from 2,770 to 2,370 (about 14%).
Native updates and instant layouts are unchanged. Closed house remains at
400 guarded reads and zero mod instant layouts. The toolbar is stubbed in this
fixture, so these counts exclude its work. None of these figures measures FPS.

Stable public release remains 0.3.6; beta 2's successful owner test does not
automatically validate this candidate.

Install with the game closed. Repeat slot 3 with Mewjector plus this mod only:
open Storage, scroll down and back, hover items, close and reopen. Confirm no
post-close lag returns. Check search/filter/reset and popup click blocking.
On a backed-up test campaign, check item transfers and pre-adventure equipment.

If performance still needs work, capture a short CPU profile of the affected
open/scrolling state before changing toolbar refresh or virtualizing drawers.
Those larger changes are deferred. Compatibility and manager mappings are
unchanged from beta 2; in-game behavior and frame times remain owner checks.
