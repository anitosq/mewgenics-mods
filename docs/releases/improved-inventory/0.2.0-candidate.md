# Improved Inventory 0.2.0 candidate

Status: development tests in progress; not published. The published download is
still 0.1.0. This update fixes the Adventure / Lock In crash and adds filters
and scrolling to pre-adventure equipment selection.

## Crash and implementation

The 25 September crash log maps to `iq_is_open` calling the house-manager lookup
with a retained panel entity after the house scene was destroyed. The global
input callback outlives that screen. It now validates retained object identity
and scene state before using a view, and resolves the house manager only in the
live native layout callback. UI renderers and item drawers also validate pooled
object generation and identity before access.

Equipment selection uses `InventoryScreen2` and `InventoryItemBox`, which have
different fields and coordinate conventions from the house drawers. Its adapter
collects unassigned Storage items and leaves cat equipment slots native. A
six-column, five-row viewport leaves room for Lock In. Search and all facets use
the existing metadata cache. Native assignment, unequipping and sorting rebuild
the view. Backpack mode remains native.

Four additional hooks have executable-hash and entry-byte checks. The full
12-hook plan must install before either UI adapter activates.

## Observed results

- Equipment screen loaded the post-crash campaign with 94 available items.
- Wheel scrolling and directional indicators worked with 30 visible cells.
- Search narrowed to Cow Skull; an unmatched query showed an empty grid.
- Equipping the last search result left the toolbar usable with zero matches.
  Unequipping returned the item and updated counts.
- Worn filter showed seven worn items. Very Rare showed seven items in the
  earlier run. Bone set selection showed two available items while Cow Skull
  was equipped, then three after unequipping.
- Set and rarity popups appeared above the grid after item assignment changes.
- Cat switching worked; Lock In proceeded to the adventure route screen.
- A further session opened house inventory, closed it, and reached equipment
  selection with 94 items without crashing. User input occurred during the
  transition; the equipment screen was inspected afterward. Evidence is in
  `work/backups/adventure-transition-06/`.
- Normal exit succeeded after each completed diagnostic session.

Offline fixtures cover unreadable/recycled/destructing references, rectangular
scroll reachability through 1,024 items, filter predicates and each partial hook
installation failure. They do not establish visual correctness or frame rate.
