# Improved Inventory 0.2.0 candidate

Status: user confirmed revised equipment appearance and smoother equipment
assignment with the subsequent hit-test fix. Performance build installed through
Vortex and deployed files verified.
Published as 0.2.0; see the [publication record](0.2.0-publication.md).
This update fixes the Adventure / Lock In crash and adds filters
and scrolling to pre-adventure equipment selection.

## Crash and implementation

The 25 September crash log maps to `iq_is_open` calling the house-manager lookup
with a retained panel entity after the house scene was destroyed. The global
input callback outlives that screen. It now validates retained object identity
and scene state before using a view, and resolves the house manager only in the
live native layout callback. UI renderers and item drawers also validate pooled
object generation and identity before access.

Equipment selection uses `InventoryScreen2` and `InventoryItemBox`, which have
different fields and coordinate conventions from the house drawers. Its adapter
collects unassigned Storage items and leaves cat equipment slots native. A
six-column, five-row viewport leaves room for Lock In. Search and all facets use
the existing metadata cache. Native assignment, unequipping and sorting rebuild
the view. Backpack mode remains native.

Four additional hooks have executable-hash and entry-byte checks. The full
12-hook plan must install before either UI adapter activates.

## Equipment performance investigation

The global native button hit-test hook scanned the full inventory for each
button and validated every candidate drawer before comparing its button pointer.
The equipment screen calls this hook repeatedly. A popup made every drawer a
candidate; a closed popup still checked offscreen/filtered drawers.

The fix indexes drawer and button pointers when a grid is captured and clears
the indexes before native rebuilds. Unrelated buttons return immediately;
matching blocked buttons retain scene, pooled-reference, button and item-ID
checks. Drawer updates also use the index instead of scanning the full view.

The native fixture exercises the actual new hit-test handler with real guarded
memory reads, including unrelated buttons, popup blocking, both drawer layouts,
recycled/unreadable objects, changed item IDs/buttons and smaller/empty rebuilt
views. For 60 simulated frames with 94 items, 150 buttons and a popup open,
guarded reads fell from 1,751,220 to 22,560. One local timing was 484.250 ms vs
5.503 ms total. These are component measurements, not in-game frame times.
