# Improved Inventory 0.4.0-beta.6 candidate

## Stage and scope

Prepared on 22 October 2026 after the owner reported that Improved Inventory
no longer appeared with 0.4.0-beta.5. It returns to the 0.4.0-beta.4
behavior and drops the Trash pre-size completely. Backpack support, the
capacity-limited Storage sizes and the probes remain. No installation,
deployment, game launch or save access was performed.

## Evidence

- Owner log 11:58–12:11 (Mewtator, 0.4.0-beta.5, Storage 5, Trash 5). The
  house load created Storage backgrounds (`InventoryGridBGBox` from
  `211c4f`) but no Trash backgrounds (`2120f0`, present in beta.3 and beta.4
  logs). No `Layout test` line followed at load or later, so every house
  capture was rejected and no mod control was created.
- Cause: the native layout builds Trash backgrounds only when the Trash column
  count changes. At `212042` it compares the count saved at entry with the
  final count (`cmp [rsp+0x70], r13d` / `je`). The beta.5 pre-size wrote the
  final count before the call, so the counts matched, no backgrounds were
  built, and `backgrounds != columns²` failed the capture. In beta.4 the
  pre-size never ran (new menus hold 0), so beta.4 was unaffected.
- The 12:05–12:11 access violations are in `QuickCleanup.dll+0x151F`
  (handled, `fatal=0`). They are unrelated to Improved Inventory.

## Changes

- Removed the Trash pre-size and the click-time native rebuild. The mod again
  never writes a native layout count. A fixed Trash size caps the native
  grid, which grows with its items from 4x4.
- A larger Trash than the native grid would need mod-created background
  cells. That remains possible future work, not attempted here.

## Offline checks

- The native source differs from 0.4.0-beta.4 only in the click comment;
  that beta.4 pre-size never ran in the owner's logs.
