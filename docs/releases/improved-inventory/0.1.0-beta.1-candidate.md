## Build and installation evidence

validation, release compilation and release guard tests. Guard tests exercise
the executable identity, asset hashes and enabled asset path, including quoted,
Unicode, spaced and case-varied paths. Native hook-plan tests cover preflight
failure and every partial installation failure. The diagnostic build and its
guards also passed. GitHub checks passed for the source commit:
[CI run](https://github.com/anitosq/mewgenics-mods/actions/runs/36088043156).

and deployed it, and registered the InventoryQoL asset folder in Load Order.
The installed extension's actual installer functions were also exercised by
`tools/check_vortex_package.mjs` against the payload manifest.

All nine staged files match their archive hashes. Vortex skips CHANGELOG.md
during deployment; the other eight deployed files match. Its ownership marker
files are additional manager metadata, not archive payload. The top-level
`mods/InventoryQoL.dll` is discovered by the existing `ScanPath=mods`; matching
assets are in `mods/InventoryQoL/`. No numbered DLL load-order entry or
chainloader.ini edit was needed. The configuration remained byte-identical.

Vortex generated a Custom Launch command containing the exact InventoryQoL
asset path alongside the existing asset mods. The Steam handoff prompted for
the custom arguments; after confirmation the game started and logged:
`Inventory QoL enabled; all UI hooks installed.` No diagnostic runner, marker
or environment switch was used to activate the mod.

The local archive import appears in Vortex under its filename, with missing
source metadata and no version displayed. Embedded description.json is not
verified as a source of Vortex's displayed version. Check Nexus-supplied
version/update metadata when testing the first hosted download.

## In-game smoke test

Used a temporary campaign copy in slot 3 with the existing mod collection
enabled, including BiggerWallet, item overrides, VisibleSetItemMarkers and
SetBonusTooltips. No inventory transfer or day advance was performed.

- Opened Storage/Trash: 92 Storage items, 0 Trash items, six-column readable
  Storage grid and down arrow. Empty Trash retained its native grid background.
- Search/type/rarity/set controls rendered in the native font.
- Rarity menu rendered its title, Any row and four options with native art.
- Selecting Rare produced 29 Storage items; Reset restored 92.
- Down scrolled one row and revealed the up arrow without shrinking the grid.
- Existing set markers remained visible; hovering Damage Transmitter showed
  its Transmitter Set Bonus tooltip and the normal item/status tooltips.
- Closed inventory, selected Save and Quit to Desktop, and restored the
  original slot 3. All pre-existing save files then matched their pre-test
  hashes; loader configuration was unchanged.

The loader recorded exit exception `0xE06D7363`, with raw stack candidates
predominantly in UIAutomationCore. This resembles the previously recorded
exception also reproduced without our DLL; it does not establish causation
or certify clean shutdown. No dump was written successfully in this run.
Keep shutdown comparison open; see the [native notes](../../research/native-inventory-notes.md).
