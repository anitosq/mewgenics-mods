# Improved Inventory 0.3.2 candidate

Tested 28 September 2026. Source commit f910056ecfc810e1b36ff0ce8a6fcaef714f2609.
Frozen archive: ImprovedInventory-0.3.2.zip.
SHA-256: 582429b0fb7dfd32820f25391ff5ed57373bb4d9e33d857f94a534c939e87c1b.

This changes packaging and version metadata; the inventory implementation and
SWF are unchanged from 0.3.1. One ZIP contains a nested DLL and asset folder.
A declarative FOMOD maps it to Vortex's game-root deployment layout; Mewtator's
importer selects the mod folder and ignores the installer XML.

## Validation

- Release build and all shared fixtures passed: 13 Python tests, browser model,
  native hooks/filter/cache/lifetime/hit-testing, asset guards and font checks.
- Installed frozen ZIP through Vortex 2.7.1 with Mewgenics extension 0.4.0,
  Default profile and the existing mod collection. Removed old versions and
  deployed before installing, following the bundled upgrade instructions.
- Nine staged and eight deployed payloads match the manifest. Vortex omits
  CHANGELOG.md. One DLL, no .vortex_backup files, unchanged chainloader.ini.
- After old installed metadata was removed, Load Order discovered the folder
  and generated its launch argument. Unchecking removed the argument and the
  compiled asset gate rejected startup; rechecking restored it and passed.
  Its thumbnail says "Not managed by Vortex" because FOMOD does not populate
  the extension's modName association. Installation is managed in Mods; this
  load-order label does not prevent the checkbox or launch from working.
- Vortex Play reached Steam's custom-arguments confirmation; accepting it
  launched the game. The initial handoff process produced a loader C++ exception
  report before the prompt was accepted; this was not a gameplay crash.
- Copied slot 3: Storage/Trash controls rendered, arrow scrolling changed rows,
  and the set menu showed separate counts. No items transferred or day advanced.
  Wheel input sent by the automation did not move the grid in this run; arrow
  scrolling was observed. Do not count this as a new wheel-input validation.
- Actual pinned Mewtator services imported/replaced the frozen ZIP into a path
  outside the game directory containing spaces. Imported hashes matched; stale
  replacement files were removed; discovery found one DLL and none when disabled.
- Mewtator GameLauncherService generated its manifest and launched the imported
  mod with only Mewjector. Copied slot 3 opened equipment assignment; set counts
  rendered and selecting Bone filtered the grid to three items.
- Both sessions closed with Save and Quit to Desktop. Main save hashes were
  unchanged; copied slot 3 and temporary loader configuration were restored.
  The first monitor lacked its psutil dependency, so its restoration was done
  explicitly after normal exit. The Mewtator monitor completed restoration itself.

Game: Windows x64 Steam build 25143593 / 1.1.21239, executable hash from
compatibility.json. Loader: Mewjector runtime 3.0 / API v3 (Nexus package 3.3).
Mewtator source: dd48fd8c04c9257af346363bd8fc7384308fd587.

## Scope and remaining checks

This is service-level Mewtator integration plus observed in-game behavior,
not automation of Mewtator's GUI. Native inventory behavior retains the previous
release's broader test coverage. Normal exit still records the C++ exception
previously reproduced without our mod; its cause remains unresolved.

A direct cross-layout Nexus upgrade is not claimed: users updating Vortex from
0.3.1 or earlier must remove the old mod and deploy before installing 0.3.2.
Earlier universal-layout disable/remove/reinstall tests are recorded in the
[packaging investigation](../../research/improved-inventory-universal-package.md).
No manager extension, loader setting or duplicate DLL is shipped as a workaround.
