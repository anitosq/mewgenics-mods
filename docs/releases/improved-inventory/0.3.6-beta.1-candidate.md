## Reproduction and cause

The owner used the published 0.3.5 archive, the official Mewjector v3.4 release
and the official Mewtator v0.6.0 release (its window identifies itself as v1.0.0).
The test ran a separate copy of supported game build 25143593 / 1.1.21239, with
only Improved Inventory enabled and a copy of campaign 1 in slot 3. The owner
reported vanilla Storage and supplied screenshots. Campaign 1 remained unchanged.

The log shows the entry-point fallback spawning Mewjector's asynchronous loader.
About 1.18 seconds later, Mewjector loads our DLL and installs the hook at RVA
0x9B9970. The log ends without our initialization-start or activation messages,
despite the owner reaching Storage. This matches the player's supplied excerpt.
Our initialization depended on a one-time startup function that had already
passed before the late hook could observe it. Offline importer, discovery and
asset-path checks passed because they never exercised this startup timing.

Private evidence is under `work/improved-inventory-report-20261009/local-test/`:
`failed-baseline/chainloader.log`, screenshot copies and `session.json`.
The isolated game files, owner screenshots and save backups are not distributable.

## Change

Use the existing renderer-creation hook at RVA 0x5A3D0 as the once-only
initialization trigger. UI creation recurs after startup. Install that hook
once during loading; the remaining hook plan excludes it. Diagnostic mode
still installs its original renderer/grid pair. No worker thread is added.

Preserve PE and entry-byte validation before registering the initial hook,
then asset pairing, the full executable hash, and complete hook-plan preflight
before enabling layout changes. Preserve the original renderer arguments and
return value even if initialization rejects the configuration. Add a load-stage
message so waiting for UI creation can be distinguished from activation.

## Offline evidence

- The new fixture exercises the production renderer callback with no one-time

- The startup regression is part of `tools/test_release_guard.py`, so the normal
