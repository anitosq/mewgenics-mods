# Improved Inventory 0.4.0-beta.1 candidate

## Stage and scope

Superseded by [0.4.0-beta.2](0.4.0-beta.2-candidate.md) before owner testing.

Prepared for owner testing on 22 October 2026. It builds on the untested
0.3.8-beta.1 performance work and adds two owner requests:

- A Grid button beside the Storage/Trash counts cycles 5x5, 6x6 (default),
  7x7, 8x8, 10x10 and Auto. Each size caps the native column count: the
  game's grid still grows up to it, then scrolls. Auto never caps, matching
  the unmodded growing grid. Equipment selection uses the same cap with five
  rows per six columns (6x5, 8x6, 10x8). The choice is stored in
  `%LOCALAPPDATA%\ImprovedInventory\settings.ini`; missing, unwritable or
  damaged files keep 6x6.
- Set labels drop each language's "Set Bonus" wording. The French
  `Bonus d'ensemble&nbsp;: alliage&nbsp;!` previously left only "Bonu.." in the
  toolbar and a truncated prefix in the set list.

Not a published release. No installation, deployment, game launch or save
access was performed for this candidate.

## Implementation evidence

- `SETBONUS_*_NAME` in the supported build's `resources.gpak` (101 sets)
  uses a different affix per language: en suffix ` Set Bonus!`; fr prefix
  `Bonus d'ensemble&nbsp;: ` with `&nbsp;!`; sp `¡Bonificación de conjunto
  (de)`; de `Setbonus:`; it `Bonus Set:`; pt-br `Bônus de Conjunto (de)`;
  ru `Бонус ... набора` in both word orders; ko/ja/zh-cn suffixes, zh-cn with
  zero-width spaces. Only these known affixes are removed; other text and
  fallback IDs remain visible. The first letter is capitalized.
- Short names are stored at set registration, so the set list sorts and
  searches by the visible name. Item search still includes the set name.
- The column cap replaces the fixed six-column constant. Changing it
  repositions the existing native backgrounds and drawers of the open view;
  no game object is allocated, and scrolling resets to the first row.
  Background scale and position derive from the captured native column count
  and scale, so repeated changes do not accumulate.
- Larger caps make more items visible, so open-inventory native updates rise
  with the visible cell count (up to 100 at 10x10, more with Auto).

## Offline checks

- Python reader tests, browser model tests (Node.js v24.21.0) and all native
  assertion fixtures, including the new `native_grid` fixture, pass.
- `native_grid` covers the size cycle, caps against native growth, equipment
  rows, button labels, settings parsing/round trips and damaged input, and
  real set-name strings from all ten game languages.
- The toolbar fixture checks the Grid label, its cache invalidation on change,
  control recreation and hiding during equipment selection.
- `build_native_probe.py` now accepts a release build without the local
  research report when the executable matches `compatibility.json`. That hash
  pins the bytes the report's reference checks covered. Diagnostic builds and
  machines with the report keep the original check.

## Owner test required

Install the beta through the usual manager after closing the game, on a
backed-up campaign copy. In Storage:

- Click Grid repeatedly: each size, then Auto. Check icon size, scrolling,
  arrows, wheel input, tooltips and the Trash grid at each step.
- Leave and reopen the house; restart the game: the chosen size remains.
- With Auto and a large inventory, check responsiveness.
- Open the set filter in French: names such as "Alliage" appear without
  "Bonus d'ensemble". Select one set; the toolbar shows its name.
- Pre-adventure equipment: check the grid for the chosen size.

Fixture results do not establish visual alignment, button placement, sound or
frame rate. The Grid button's position on the count row is unverified in game.
