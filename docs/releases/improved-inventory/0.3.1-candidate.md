# Improved Inventory 0.3.1 candidate

Started 28 September 2026. Published with user authorization; see the
[publication record](0.3.1-publication.md) for host verification.

## Scope

Support Mewtator's enabled-mod DLL discovery in an external mods directory.
The startup gate accepts assets beside the DLL or in its containing directory,
requires the exact enabled path, and verifies both asset hashes. If both possible
folders are enabled, it stays inactive rather than choosing one.

The regular archive retains the Vortex/default Mewjector scan layout. A second
Mewtator archive puts the same DLL inside ImprovedInventory/. The build produces
both archives from identical payload bytes. Runtime UI code is unchanged.

## External manifest runtime check

Used the installed supported game and Mewjector v3.0 with only Improved Inventory.
Extracted the frozen Mewtator ZIP into an external directory containing spaces.
The actual upstream DLL service generated the manifest; Mewjector loaded exactly
one DLL from it and all UI hooks activated. Launch used the same arguments,
working directory and Steam environment as Mewtator's DirectLaunchStrategy.
This exercised its discovery/manifest service and the game, not Mewtator's GUI.

Opened a backed-up home campaign in slot 3. Storage showed 92 items and Trash
zero, with the full toolbar and fixed-size grid. The Sets popup showed separate
counts; selecting Bionic reduced Storage to seven items. No item was moved or
day advanced. Main campaign unchanged, original empty slot 3 and loader config
restored after Save and Quit to Desktop. Vortex's deployed files were untouched.
Private evidence: `work/backups/mewtator-patch-20260928-104930`.

On exit, Mewjector recorded C++ exception `0xE06D7363` with a raw stack dominated
by UIAutomationCore. A comparison launch with zero mod DLLs reproduced the same
exception code and UIAutomationCore stack on normal menu exit. It is therefore
not specific to this patch; the exact cause is unresolved. Comparison evidence:
`work/backups/mewtator-patch-20260928-105422`. Its saves and config were restored
and main campaign unchanged as well. Do not report these as crash-free exits.

## Regular package runtime check

Extracted the frozen regular ZIP and pointed Mewjector's nonrecursive ScanPath
at that directory. Only Improved Inventory was loaded; the sibling asset folder
was enabled through the game's launch arguments. All UI hooks activated.

Opened a backed-up equipment-selection campaign in slot 3. The toolbar and
six-column grid rendered, the Sets popup showed Available counts, and the down
arrow advanced one row and revealed the up arrow. The equipment screen had no
Storage count line, as intended. No items were assigned and Lock In was not used.
This was a visual and interaction check, not a frame-time measurement.

After Save and Quit to Desktop, the main campaign hash was unchanged and the
original empty slot 3 and loader configuration were restored. The same exit
exception described above was recorded. Vortex's deployed 0.3.0 files were
untouched. Private evidence: `work/backups/mewtator-patch-20260928-105530`.
Screenshots are retained beside the frozen archives under `outputs/releases/`.

## Publication copy

Replace the live 0.3.0 Mewtator workaround only when 0.3.1 is published:

> For Mewtator, download Improved Inventory - Mewtator, extract it into your
> configured mods directory, and enable the mod and DLL Mod Support. Launch
> through Mewtator. Use only one download; remove an earlier manual or Vortex
> installation before switching.

Keep the Nexus display names version-free. Use Improved Inventory for the regular
download and Improved Inventory - Mewtator for the alternate package.
