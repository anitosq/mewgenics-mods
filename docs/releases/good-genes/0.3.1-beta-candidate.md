## Change and evidence

Read-only inspection of the supported executable confirmed that five birth
blocks mirror one selected side onto its counterpart. Five additional guarded
branches skip both copy directions for arms, legs, ears, eyes and eyebrows.
Each branch replaces a complete five-byte COMISD after the native RNG call.
All five RNG calls remain, as do head visibility refresh, per-side parental
selection, skill inheritance and event/combat mutation choices.

Independent ordinary appearances also survive; paired mutations still count
once when their group and ID match. Two parents with competing mutations in
the same side still contribute only one selected ID. A head can hide facial
parts and effects. There is no added mutation slot or guarantee that all
parental mutations survive competing selections.

Normal births add four log lines: base stats, selected parental skills,
unpaired part IDs and paired IDs in left/right order. Part logs precede native
head visibility refresh and do not represent effective mutation counts.
Unknown parental definitions produce a native-fallback diagnostic. Startup
confirms version and enabled birth logging. No new UI or periodic logging.

Compilation with warnings as errors succeeded. Generated patch bytes were
disassembled and all ten branch destinations inspected, including the five
new pair-copy bypasses. The packager verified source/build hashes, ten
allowlisted files and FOMOD mappings. The frozen ZIP and every payload match
the trusted manifest. VERSION, the compiled DLL startup string, archive name
and package metadata all report 0.3.1.beta.

The existing gate regression check was extended for all five pairs but was
not executed under the owner's standing test restriction. Compilation,
static inspection and archive checks are not gameplay confirmation. No DLL
loading, installation, game launch, save modification, upload, tag or push.
